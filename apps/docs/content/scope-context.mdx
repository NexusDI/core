# Scoping Requests outside Node

Code deep in a service reads the request's scope through `scopes.current()` when the adapter runs the request inside a scope runner, an object with `run(scope, fn)` that an adapter's `scopes` option takes. `nodeScopes()` from `@nexusdi/node` is that runner on Node, and it needs `AsyncLocalStorage` from `node:async_hooks`. A runtime without that module needs a runner of its own.

## Which Runtimes Take `nodeScopes()`

`nodeScopes()` runs wherever the runtime provides `node:async_hooks`, the package name notwithstanding. Cloudflare Workers, Deno and Bun do, and the `adapter-runtimes` CI job runs `nodeScopes()` on each of them. Workers needs compatibility date 2026-08-04 or later, or the `nodejs_compat` flag. Vercel documents the module on Vercel Edge, and no CI leg runs `nodeScopes()` there. [Running on Edge Runtimes](/edge/) gives the Worker configuration.

This works where the framework calls the handler synchronously inside `next()`, as Hono does. React Router loaders, and Fastify handlers after body parsing, run after `run()` returns and read `undefined`; use `di.inject` there. After an `await`, `current()` returns `undefined` too, because `run()` has already restored the previous value. Read the scope with this runner only in code that runs synchronously inside the handler, before its first `await`, and pass every other dependency through `di.inject`, which needs no ambient scope.

To see the limit, make the handler `async` and add `await Promise.resolve();` before the read. The reply becomes `none`. Remove the line again.
