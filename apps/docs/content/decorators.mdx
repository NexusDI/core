# Writing Providers with Decorators

While `static deps` and `defineModule()` are the foundation of NexusDI, you can use decorators to make your dependency declarations more readable and concise.

NexusDI provides a set of standard (TC39) decorators that act as syntactic sugar. They write the same `static deps` and `defineModule` definitions that you would write by hand. This means a decorated class and an undecorated class wire exactly the same way.

## Tooling and Compatibility

Because these are standard decorators, they require a toolchain that can compile them: `tsc`, TypeScript 7, esbuild, SWC, Babel, Bun, Deno, or Vite with its Babel plugin. Plain Vite 8 and Node's type stripping cannot compile them.

**Important:** You must leave `experimentalDecorators` and `emitDecoratorMetadata` **disabled** in your `tsconfig.json`. NexusDI does not rely on compiler-emitted metadata; every dependency is explicitly named via a token in the decorator.
