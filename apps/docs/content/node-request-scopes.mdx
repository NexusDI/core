# Scoping Node.js HTTP Requests

In a web server, you often need a "request scope"—a set of dependencies that are created when a request arrives and destroyed when the response is sent. 

The `@nexusdi/node` package provides `nodeScopes()`, which leverages Node's `AsyncLocalStorage` to bind a NexusDI scope to the current asynchronous execution context. This allows you to access the request's scope deep within your call chain without having to pass the scope object manually through every function.

## Running Handlers in a Scope

To use request scopes, you wrap your request handler in `scopes.run()`. This creates a new scope for the request and makes it available to everything that happens inside that function.

### The `REQUEST` Token
By using `nodeScopes()`, you can inject the `REQUEST` token into any scoped provider. This allows your services to access request-specific data (like user IDs or headers) directly.

To get full type safety, augment the `NexusRequest` interface:

```ts no-run
declare module '@nexusdi/core' {
  interface NexusRequest {
    mission: { id: string; target: string };
  }
}
```

## Accessing the Current Scope

If you are in a function that was called inside a `run()` block, you can retrieve the current scope using `scopes.current()`.


If `current()` is called outside of a `run()` block, it returns `undefined`.

## Concurrency and Isolation

Because `nodeScopes()` uses `AsyncLocalStorage`, it is completely safe for concurrent requests. Even if a thousand requests are being handled simultaneously, `scopes.current()` will always return the scope associated with the specific async chain of the current request.

## Integrating with `node:http`

Integrating NexusDI scopes into a standard Node.js server is straightforward. You create a scope for every incoming request and execute your handler within that scope's context.

```ts no-run
import { createServer } from 'node:http';

createServer(async (req, res) => {
  const url = new URL(req.url ?? '/', 'http://localhost');
  const id = url.searchParams.get('mission') ?? 'survey-7';
  const reply = await dispatch({ mission: { id, target: 'Kepler-442b' } });
  res.end(reply);
}).listen(3000);
```

By doing this, every request gets its own isolated set of scoped providers, which are automatically disposed of when the request settles.
