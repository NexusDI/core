# How do I use NexusDI in a project that keeps experimentalDecorators?

Declare deps with `static deps` and bind tokens with `provide()`, and collect the bindings in `defineModule()`. None of them is a decorator, so they work under every compiler flag, `experimentalDecorators` and `emitDecoratorMetadata` included. A project that keeps the flag for another library uses NexusDI this way and leaves `@nexusdi/decorators` out.

## `@nexusdi/decorators` throws `NEXUS_LEGACY_DECORATORS` under the flag

The NexusDI decorators are standard (TC39) decorators. With `experimentalDecorators` set, TypeScript calls a class decorator with the class alone, where a standard decorator receives a context object as well. Each NexusDI decorator checks for that context and throws [NEXUS_LEGACY_DECORATORS](/errors/NEXUS_LEGACY_DECORATORS/) when the class is defined, which happens when its file loads. The region makes the legacy call by hand:

```

Try it: save the region as `legacy.ts` and run `npx tsx legacy.ts`. It prints the message and its fix line.

In a project that sets the flag, `tsc` stops first. It reports TS1238 on a decorated class (`@Injectable` or `@Module`) and says the runtime invokes the decorator with 1 argument where it expects 2, and TS1240 on an `@Inject` accessor. Run the file anyway and the same error is thrown when the class is defined. Two fixes exist. Remove `experimentalDecorators` from `tsconfig.json` if no other library needs it, and the decorators compile as written. If the flag stays, drop the decorators from the NexusDI classes and use the two sections below.

## Wire NexusDI without decorators

`static deps = [REACTOR] as const` lists the tokens the constructor takes, and TypeScript checks the tuple against the constructor at the `provide()` call. `provide(COMPUTER, { useClass: QuantumComputer })` reads it, and `defineModule()` holds the providers. The same code compiles with `experimentalDecorators` on or off.

```

Try it: save the region as `wire.ts` and run `npx tsx wire.ts`. It prints `ShipComputer online. Reactor output 1.21 GW.` Add `"experimentalDecorators": true` to the `compilerOptions` of your `tsconfig.json` and run it again: `npx tsc` reports nothing and the output does not change. Now change `static deps = [REACTOR] as const` to `[COMPUTER] as const`. `npx tsc` reports TS2769 on the `provide(COMPUTER, { useClass: QuantumComputer })` line, because `COMPUTER` is not a `Token<IReactorCore>`. Change it back.

## Bind a class you cannot edit with `provide()`

A class from another package carries no `static deps`, and its source is out of reach. `provide(COMPUTER, { useClass: VendorComputer, deps: [REACTOR] })` declares its deps at the binding. An explicit `deps` option also wins over a `static deps` the class carries.

Try it: save the region as `vendor.ts` and run `npx tsx vendor.ts`. It prints `VendorComputer online. Reactor output 1.21 GW.` Delete `deps: [REACTOR]` from the binding and run it again. `Nexus.create` rejects with [NEXUS_BLUEPRINT_INVALID](/errors/NEXUS_BLUEPRINT_INVALID/), whose `errors` list holds [NEXUS_MISSING_DEPS](/errors/NEXUS_MISSING_DEPS/), because nothing says what the constructor takes. Put `deps: [REACTOR]` back and the status line returns.
