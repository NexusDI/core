# Modules

As your application grows, putting every provider into a single global list becomes unmanageable. You lose the ability to encapsulate logic, and it becomes difficult to track where dependencies are coming from.

**Modules** solve this by grouping related providers into bounded contexts. A module defines its own internal set of providers and explicitly chooses which ones to share with the rest of the application.

## Encapsulation and Visibility

The primary purpose of a module is to control visibility. 

- **Private Providers:** By default, everything provided inside a module is private. Only other providers within the same module can use them.
- **Public Exports:** To make a provider available to other modules, you must list its token in the `exports` array.

```ts file=examples/meridian/src/pages/modules.md region=exports
```

This pattern prevents "leaky abstractions." For example, a `DatabaseModule` might provide a `ConnectionPool` internally, but only export a `Repository` to the rest of the app. The rest of the app doesn't need to know the pool exists, and they cannot accidentally depend on it.

## Module Integration

Modules interact through `imports`. If Module A imports Module B, Module A can see everything that Module B exports.

### Global Modules

Some providers are truly universal (like configuration or logging) and are needed by almost every module. Instead of importing them everywhere, you can mark a module as `global: true`.

```ts file=examples/meridian/src/pages/modules.md region=global
```

A global module's exports are visible to every module in the graph automatically, provided the global module is included in the graph at least once.

## Swapping Implementations

Because modules are defined by the tokens they export rather than the classes they use, you can swap an entire module for another as long as the exported tokens remain the same.

This is incredibly powerful for testing. You can replace a `ProductionEngineeringModule` with a `SimulatorEngineeringModule` that exports the same `COMPUTER` token but uses a simulated reactor under the hood.

```ts file=examples/meridian/src/pages/modules.md region=swap
```

The consuming code doesn't change; it just receives a different implementation of the same token.
