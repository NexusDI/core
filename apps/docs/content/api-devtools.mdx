# `@nexusdi/devtools`

A container that wires the wrong provider or starts slowly leaves a developer asking what it holds and what it did while it started. `@nexusdi/devtools` answers both. `devtools()` is a development plugin that lets `graph(ship)` return the container's compiled graph as plain JSON. It hands every lifecycle event to the callback in its `trace` option, and it words errors with `@nexusdi/errors`. `inspect(root)` returns the same graph from the compiler alone, building nothing, for a CLI or a CI job, and `trace(fn)` is a plugin that only reports events. `toMermaid()` and `toDot()` draw a graph as a Mermaid flowchart or a Graphviz digraph, with a load import as a dashed edge, and `parseGraph()` reads a saved graph back and checks its shape. Each module in the JSON carries a `loadImports` list of the module ids a load import added to its `imports` list beyond the modules it imports itself, and a saved graph without the field reads as an empty list. Each export has one entry below, with what the package's tests state about it.

`profile()` is a plugin that records where startup time goes, each provider's build included, and the profiler's `report()` method returns it as plain JSON. `profileTable()`, `criticalPath()`, `toChromeTrace()` and `toPerfettoTrace()` read that report, and `parseProfileReport()` reads a saved one back. `liveSink()` from `@nexusdi/devtools/live` returns a sink that `profile({ live })` draws each run through in the Chrome DevTools Performance panel, in Chromium 134 and later.

## `profileStartup`

<!-- reference @nexusdi/devtools#profileStartup example=profile-startup -->

`profileStartup(root)` takes any root `Nexus.create` takes. A root object lists the modules it imports in `imports`. `profileStartup(root, { load: [{ module, imports }] })` loads each entry in order, as `load(module, { imports })` does.
