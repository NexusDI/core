# `@nexusdi/react-router`

A request-scoped service needs one scope per request, disposed when the response is done. React Router finishes the middleware chain before the server writes the body, and deferred data keeps streaming after it, so a scope disposed when the middleware returns is gone while a deferred value still reads it. `const di = nexus(ship)` gives a `NexusRouter`: `di.middleware` in the root route's `middleware` export puts a scope handle on the router context under `NEXUS_SCOPE`. The first `di.inject` loader or action creates the scope, which loaders that run in parallel share, or the middleware creates it at once with the `scopes` option. The scope is disposed once, when the streamed body ends, errors or is cancelled, or when the request's signal aborts. A NexusDI error from creating the scope or resolving a loader's deps is thrown as a `Response` with status 500 or 503, which renders the nearest error boundary. A test puts `existingScope(scope)` under `NEXUS_SCOPE` and calls a loader directly. Each export has one entry below, with what the package's tests state about it.
