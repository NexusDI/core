# Scopes and the REQUEST Token

Most applications have two types of state: **Global state** (like a database connection pool) and **Request state** (like the current user or a transaction ID).

While singletons handle global state perfectly, using them for request-specific data is impossible in a concurrent environment. **Scopes** solve this by creating a temporary scope for a single unit of work.

## What is a Scope?

A scope is a short-lived container created from a root container. It inherits all the singletons from the root but maintains its own independent instances of any provider marked as `lifetime: 'scoped'`.

## The `REQUEST` Token

To make a scope useful, you need to pass external data (like an HTTP request) into it. NexusDI provides a built-in `REQUEST` token for this purpose.

When you call `createScope({ request })`, the object you pass as the request is bound to the `REQUEST` token for the duration of that scope.

### Typing your Request

To get full TypeScript support, augment the `NexusRequest` interface in a `.d.ts` file:

```ts no-run
import '@nexusdi/core';

declare module '@nexusdi/core' {
  interface NexusRequest {
    mission: { id: string; target: string };
  }
}
```

## The Captive Dependency Rule

One of the most important rules in NexusDI is that **a singleton cannot depend on a scoped provider**.

If a singleton (which lasts forever) depended on a scoped provider (which lasts for one request), the singleton would "capture" the first request's instance and hold onto it forever. This is a **Captive Dependency**.

NexusDI prevents this at startup. If it detects a singleton reaching a scoped provider, `Nexus.create` rejects with `NEXUS_BLUEPRINT_INVALID`, whose `errors` list holds `NEXUS_LIFETIME_VIOLATION`.

## Scoped Execution Details

### Eager vs Lazy Scoped Providers

- **Scoped Factories:** By default, these run immediately when `createScope()` is called.
- **Scoped Classes:** These are created lazily on the first `get()` within the scope.

If you have heavy work (like starting a DB transaction), put it in a scoped class rather than a factory to ensure it only runs if actually requested.
