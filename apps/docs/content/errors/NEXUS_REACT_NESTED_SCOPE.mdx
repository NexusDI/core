# NEXUS_REACT_NESTED_SCOPE

`ScopeProvider` from `@nexusdi/react` throws `NEXUS_REACT_NESTED_SCOPE` in a browser render when its context already holds a scope: an outer `ScopeProvider`, or a `NexusProvider` given `scope`. Core 0.4 scopes do not nest, and the package refuses both silent choices. Reusing the outer scope would give the inner subtree the outer subtree's scoped instances, and a new scope beside it would hide them. On the server and during hydration a `ScopeProvider` renders its `fallback`, so a React Router server render whose `NexusProvider` carries the request scope never throws it.
