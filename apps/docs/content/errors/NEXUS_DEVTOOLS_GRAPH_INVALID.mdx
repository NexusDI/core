# NEXUS_DEVTOOLS_GRAPH_INVALID

`parseGraph(value)` throws `NEXUS_DEVTOOLS_GRAPH_INVALID` when `value` is not a `NexusGraph`. `parseGraph` checks every field of a graph read back with `JSON.parse`, and the error's `path` names the first field that failed. The call throws synchronously and bare. `nexusdi graph` from `@nexusdi/cli` calls `parseGraph` for a `.json` entry, and for a file that holds no graph it prints `nexusdi: <file>:` followed by this error's message, then exits with code 2. A `.json` file whose text is invalid JSON fails earlier with a different message that carries no code.

## Reproduce `NEXUS_DEVTOOLS_GRAPH_INVALID`

`parseGraph` throws `NEXUS_DEVTOOLS_GRAPH_INVALID` for a saved graph whose first provider has lost its `token` field. `@nexusdi/devtools` writes this message itself, so it carries its full text and fix line with no text pack.


Try it: run `npm install @nexusdi/devtools@next`, save the region as `parse.ts` and run `npx tsx parse.ts`. It prints three lines: the path `providers[0].token`, then the message, `[NEXUS_DEVTOOLS_GRAPH_INVALID] not a NexusGraph: providers[0].token is missing or has the wrong type.`, then the fix line, which starts `Fix: pass JSON.parse of the text that`.

## Fix `NEXUS_DEVTOOLS_GRAPH_INVALID`

`NEXUS_DEVTOOLS_GRAPH_INVALID` goes away when `parseGraph` receives what `graph(ship)` or `inspect(root)` wrote, unedited. Write the file with `JSON.stringify(graph(ship))` or `nexusdi graph --format json`, and pass `JSON.parse` of its text. `JSON.stringify(inspect(root))` writes the same shape without a container.

```ts file=examples/meridian/src/errors/NEXUS_DEVTOOLS_GRAPH_INVALID.md region=fix

```

Try it: save the region as `fixed.ts` and run `npx tsx fixed.ts`. It prints `ReactorCore`. Change `JSON.parse(text)` to `JSON.parse(text.replace('"token"', '"tokens"'))` and run it again. `npx tsc` accepts the file, and `npx tsx fixed.ts` throws an uncaught `DevtoolsError` whose first line is `DevtoolsError: [NEXUS_DEVTOOLS_GRAPH_INVALID] not a NexusGraph: providers[0].token is missing or has the wrong type.` and whose last line is `path: 'providers[0].token'`. Change the call back and the program prints `ReactorCore` again.

## Fields of `DevtoolsError`

- `code`: `'NEXUS_DEVTOOLS_GRAPH_INVALID'` or `'NEXUS_DEVTOOLS_UNREGISTERED'`.
- `path`: the first field that failed, such as `'providers[3].module'`. `parseGraph` checks the modules first, then the providers, the edges and the `imports` and `exports` of each module, so the first failure in that order wins. `'(root)'` names a value that is no object, and a top-level name such as `'modules'` names a missing list. A message that ends `is missing or has the wrong type` covers a missing field or a field of the wrong type, and a message that ends `which no module has` covers an id that points at nothing, such as `providers[0].module`. A repeated id fails at the second entry, such as `'modules[1].id'`. `null` for [NEXUS_DEVTOOLS_UNREGISTERED](/errors/NEXUS_DEVTOOLS_UNREGISTERED/).
