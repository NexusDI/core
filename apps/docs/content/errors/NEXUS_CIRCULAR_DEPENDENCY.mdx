# NEXUS_CIRCULAR_DEPENDENCY

`NEXUS_CIRCULAR_DEPENDENCY` means providers depend on each other in a cycle and no edge of the cycle is a `lazy()` dependency, so no provider in it can be built first. `Nexus.create` reports it inside [NEXUS_BLUEPRINT_INVALID](/errors/NEXUS_BLUEPRINT_INVALID/).

The error covers indirect cycles of any length, across modules too. [Why `lazy()` is opt-in](/lazy/#why-lazy-is-opt-in) says why NexusDI reports them.

## Reproduce `NEXUS_CIRCULAR_DEPENDENCY`

The region has `PlasmaRouter`, bound to `PowerRouter`, depend on `ShieldGrid`, and `DeflectorGrid`, bound to `ShieldGrid`, depend on `PowerRouter`. Without a plugin, core prints a one-line message that starts with the code and ends with the address of this page. With `errors()` from `@nexusdi/errors` registered (`npm install @nexusdi/errors@next`), the same error carries the full text and its fix.

```

Try it: save the region as `error.ts` and run `npx tsx error.ts`. It prints the one-line message, then the full text as an array of two lines, then the kinds. The `path` field lists the cycle from its first provider back to it. The `kinds` field says how each step depends on the next, and the region prints them as `required -> required`. Then save the fix region below as `fixed.ts` and run `npx tsx fixed.ts`. It prints `0.4`.

## Fix `NEXUS_CIRCULAR_DEPENDENCY`

`NEXUS_CIRCULAR_DEPENDENCY` is fixed by wrapping one edge of the cycle in `lazy()`. The dependency then receives a function that returns the instance, and the method calls it after startup. Here `PlasmaRouter` takes `lazy(SHIELD_GRID)`. [Lazy Dependencies and Cycles](/lazy/) covers the rule.

```

Try it: change `lazy(SHIELD_GRID)` in the deps of `PlasmaRouter` back to `SHIELD_GRID` in `fixed.ts` and run it again. `tsc` flags the `provide(POWER_ROUTER, ...)` call, because the constructor still expects a function. `Nexus.create` rejects with a `BlueprintError` whose message lists `[NEXUS_CIRCULAR_DEPENDENCY] path=PowerRouter,ShieldGrid,PowerRouter kinds=required,required.` Restore `lazy(SHIELD_GRID)` and the program prints `0.4` again.

The fix line that `errors()` writes names the first step of `path` that is not an alias. `path` starts at the provider of the cycle that is declared first. When that step is an `all()` dependency, wrap the whole modifier: `lazy(all(TOKEN))`. `lazy()` takes no `MultiToken` on its own, so the fix line writes `lazy(all(TOKEN))` for such a step. A cycle made only of `useExisting` aliases has no edge that `lazy()` can wrap. Point one alias at a provider outside the cycle.

## Fields of `CircularDependencyError`

`CircularDependencyError` has two fields:

- `path`: the display names along the cycle, ending with the first one again.
- `kinds`: how each step of `path` depends on the next, one fewer entry than `path`. A kind is `required`, `optional`, `all` or `alias`, where `alias` marks a `useExisting` target. When a provider depends on the next provider of `path` more than once, as in `[SHIELD_GRID, optional(SHIELD_GRID)]`, its step reports the first of those deps.
