# Trying the 0.4 Release Candidate

NexusDI 0.4 introduces major changes to the container's architecture, moving toward static graph validation. To ensure stability, the 0.4 release is published as a series of Release Candidates (RCs) before the final 0.4.0 version is released.

## What is a Release Candidate?

A Release Candidate is a version that is functionally complete but is being tested for final bugs. RCs are published under the npm `next` dist-tag.

While `latest` remains on the stable 0.3.x line, `next` points to the most recent RC. We encourage users to try the RC and report any issues to ensure the final release is as stable as possible.

## Installation

All `@nexusdi/*` packages share the same version. To try the RC, install the core and any necessary plugins using the `next` tag:

```bash
npm install @nexusdi/core@next
npm install -D @nexusdi/testing@next @nexusdi/devtools@next
```

## Verifying Your Version

You can check which version of NexusDI you have installed using `npm ls`:

```bash
npm ls @nexusdi/core
```

If you see a version like `0.4.0-rc.X`, you are running the release candidate.

## Reporting Problems

If you encounter a bug or a regression in the RC, please report it via the [RC feedback form](https://github.com/NexusDI/core/issues/new?template=04-rc-feedback.yml).

To help the maintainers fix the issue quickly, please include:
1. The output of `npm ls @nexusdi/core` and `node --version`.
2. The full error message, including the error code (e.g., `[NEXUS_MISSING_PROVIDER]`).
3. A minimal reproduction program that triggers the failure.

The maintainers label critical bugs as `rc-blocker`. A bug with this label must be fixed before 0.4.0 final is released.
