# Providers

A NexusDI provider tells the container how to build the value behind a token (an interface name from the previous page). `provide(TOKEN, options)` writes one, and its options pick the form: `useClass`, `useValue`, `useFactory` or `useExisting`.

## Declare a class's deps with `static deps`

`static deps` is the list of tokens a class's constructor takes, in parameter order, written on the class itself. `provide(COMPUTER, { useClass: QuantumComputer })` reads that list, so the provider needs no `deps` option. TypeScript checks the list against the constructor where the class is declared, so a token whose type does not fit its parameter fails to compile. Every example in these docs uses this form for the classes it owns.

The terminal prints `Reactor output 1.21 GW.` Then delete the `static deps` line and run it again. `npx tsc` reports nothing, because the class declares no list to check, and the run ends with an uncaught `NEXUS_BLUEPRINT_INVALID` error whose second line names `token=ShipComputer` and `arity=1`. Put the line back and the program prints `Reactor output 1.21 GW.` again.

## Pass `deps` to `provide()` for a class you cannot edit

`provide(TOKEN, { useClass, deps })` lists the deps on the provider, for a class whose source you do not own, such as a class from a package. The `deps` option has the same type check as `static deps`, and when a class carries both, the `deps` option wins.

Run the file anyway and `status()` throws a `TypeError`, because `reactor` is `undefined`. Change the list back to `[REACTOR]` and `npx tsc` reports nothing.

## Build a value with a NexusDI `useFactory` provider

`useFactory` builds the value with a function, and its `deps` list the tokens the function takes as arguments. `provide()` types each argument from its token, so `link` below is an `ISubspaceLink` with no annotation. ## Mark a dependency as optional with `optional()`

`optional(TOKEN)` in a deps list resolves to `undefined` when no visible provider exists for the token, where a plain token would fail `Nexus.create`. The constructor parameter takes `T | undefined`, and TypeScript checks the class against it.

Run the program: `Nexus.create` rejects with `NEXUS_BLUEPRINT_INVALID`, and the error it carries is [`NEXUS_MISSING_PROVIDER`](/errors/NEXUS_MISSING_PROVIDER/) for `SubspaceLink`, requested by `DiagnosticsPanel`. Put `optional(SUBSPACE_LINK)` back and the program prints `all systems nominal, held aboard` again.

## A class whose constructor has defaults or rest parameters

NexusDI decides whether a class without deps can be built from the class's `length`, the count of constructor parameters before the first one with a default or a rest parameter. A class whose parameters all have defaults reports a `length` of `0`, so `Nexus.create` builds it with no arguments, and each parameter takes its default.
