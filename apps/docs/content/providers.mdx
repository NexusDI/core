# Providers

Once you have defined **Tokens** to identify your dependencies, you need to tell NexusDI how to actually create the values associated with those tokens. This is the role of a **Provider**.

A provider is essentially a recipe. When the container encounters a token it needs to resolve, it looks up the assigned provider to determine if it should instantiate a class, return a static value, or run a factory function.

## The Default: Class Providers

The most common way to provide a dependency is by using a class. In NexusDI, a class can act as its own provider.

### Using `static deps`

To make a class "injectable," you define its constructor dependencies in a `static deps` array. This allows NexusDI to know exactly what to inject without needing runtime reflection.

```ts file=examples/meridian/src/pages/providers.md region=static-deps

```

By declaring `static deps`, TypeScript can verify that the tokens you've listed actually match the types expected by the constructor.

If you forget to declare `static deps` for a class with constructor parameters, `Nexus.create` will fail with `NEXUS_BLUEPRINT_INVALID`, whose `errors` list holds `NEXUS_MISSING_DEPS`, preventing a `TypeError` at runtime.

## Advanced Provider Types

Sometimes a simple class instantiation isn't enough. NexusDI provides several other ways to resolve tokens.

### Factory Providers (`useFactory`)

Factories are used when the creation logic is complex or requires asynchronous setup. A factory is simply a function that returns the value for the token.

```ts file=examples/meridian/src/pages/providers.md region=factories

```

Factories can be `async`. NexusDI awaits all async factories during the startup phase, meaning that by the time your app is "online," every dependency is already resolved and `get()` remains synchronous.

## Handling Constructor Defaults

If your class has no `static deps`, NexusDI counts its constructor parameters with `cls.length`. That count stops at the first parameter with a default or a rest parameter. A class whose parameters all have defaults counts zero and builds with its defaults. `constructor(a: X, b = 1)` still counts one and fails with `NEXUS_MISSING_DEPS`.

```ts file=examples/meridian/src/pages/providers.md region=defaults

```

If you want the container to override those defaults and inject a specific dependency, you must explicitly declare it using `static deps` or the `deps` option in `provide()`.
