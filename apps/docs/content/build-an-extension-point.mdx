# Building an Extension Point

Many libraries need to execute logic supplied by the end user, such as health checks, validation rules, or event handlers. To achieve this without the library knowing about the application's concrete modules, the library provides a way for those modules to "plug in" their own logic.

This pattern uses a `MultiToken` and a collector module. The library owns the token, and the application modules contribute to it. Because the library cannot import application modules, the application must publish its contributions by exporting the token from the contributing module. [Multi-Providers](/multi-providers/) explains the underlying rules and the order of the resulting list. This guide demonstrates how to build both the library and application sides of an extension point called `HEALTH_CHECKS`.

## Defining the Library Interface

The library must export the token, the interface for contributions, and the module that collects those contributions.

In this example, `HEALTH_CHECKS` is a `MultiToken<IHealthCheck>`. The `HealthService` implements `IHealthMonitor` and collects all contributions via `all(HEALTH_CHECKS)`. The `HealthModule` provides this service under `HEALTH_MONITOR` (a `Token<IHealthMonitor>`) and exports it.

To ensure the container can find these contributions, the library documents that contributors export the token from their own modules. A contribution that is not exported stays private to its module, and `Nexus.create` rejects it with `NEXUS_UNREAD_CONTRIBUTION` when no provider in that module reads it.

The application then imports `HealthModule` into each contributing module, binds each check using `useClass`, and exports `HEALTH_CHECKS`.

## Managing Contributor Dependencies

Contributions are providers. They can declare their own dependencies in `deps` and resolve them based on the visibility of the module they belong to.

For example, `ReactorCheck` takes `REACTOR_PROBE`, which the `Engineering` module provides. A contribution can read any token that its own module can see: its own internal providers and the exports of any modules it imports.

## Solving Circular Dependencies with `lazy(all())`

A circular dependency occurs when a contribution depends on the collector, while the collector depends on all contributions. For example, if a health check reports its status back to the `HEALTH_MONITOR`, but the monitor takes `all(HEALTH_CHECKS)`, `Nexus.create` rejects with `NEXUS_BLUEPRINT_INVALID` holding `NEXUS_CIRCULAR_DEPENDENCY`.

The library can break this cycle by using `lazy(all(HEALTH_CHECKS))`. This prevents the end-user from having to write `lazy()` in every contribution. The library then calls the returned thunk inside a method after `Nexus.create` has finished. [Contributors That Call the Collector](/multi-providers/#contributors-that-call-the-collector) illustrates the cycle, and [Lazy Dependencies and Cycles](/lazy/) explains how to handle the thunk.

## Handling Lifetime Constraints

Collectors and their contributions must share a compatible lifetime contract. If a singleton collector holds contributions for the life of the container, any scoped contribution in the graph makes `Nexus.create` reject with `NEXUS_BLUEPRINT_INVALID` holding `NEXUS_LIFETIME_VIOLATION`. This restriction also applies to `lazy(all())` edges.

## Contributions in Loaded Modules

Modules added via `ship.load()` cannot contribute to a collector through the standard provider mechanism. A loaded module that exports a contribution will trigger a `NEXUS_LOAD_CONTRIBUTION` error.

If the library must support contributions from loaded modules, provide a registry on the collector. The loaded module can then register its check in `onInit` and unregister it upon disposal. [Adding to a Collector from a Loaded Module](/load/#adding-to-a-collector-from-a-loaded-module) shows this implementation.

## Errors You Meet

Contributors and library authors typically encounter the following errors during development.

| Code                                                              | When it happens                                                                                                                                                                                    | Fix                                                                                  |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| [`NEXUS_UNREAD_CONTRIBUTION`](/errors/NEXUS_UNREAD_CONTRIBUTION/) | A module contributes to `HEALTH_CHECKS`, does not export it, and no provider in the module reads it.                                                                                               | Collect it in the module with `all()`, export the token, or remove the contribution. |
| [`NEXUS_CIRCULAR_DEPENDENCY`](/errors/NEXUS_CIRCULAR_DEPENDENCY/) | A contributor depends on the monitor, and the monitor takes `all(HEALTH_CHECKS)`. The error's `kinds` read `all -> required`.                                                                      | Take `lazy(all(HEALTH_CHECKS))` in the collector.                                    |
| [`NEXUS_LIFETIME_VIOLATION`](/errors/NEXUS_LIFETIME_VIOLATION/)   | A singleton collector reaches a scoped contribution.                                                                                                                                               | Make the contribution a singleton, or make the collector scoped.                     |
| [`NEXUS_LOAD_CONTRIBUTION`](/errors/NEXUS_LOAD_CONTRIBUTION/)     | `ship.load()` receives a module that exports a contribution to `HEALTH_CHECKS`.                                                                                                                    | Register the check from `onInit` through the collector's registry.                   |
| [`NEXUS_NOT_READY`](/errors/NEXUS_NOT_READY/)                     | A `lazy(all())` thunk runs while a contribution is not built, such as in the collector's constructor. The error's `target` names the multi token and `contributor` the first unready contribution. | Call the thunk in a method, after `Nexus.create` has finished.                       |
| [`NEXUS_INVALID_PROVIDER`](/errors/NEXUS_INVALID_PROVIDER/)       | A provider declares `lazy(HEALTH_CHECKS)`, `optional(HEALTH_CHECKS)`, `optional(all(HEALTH_CHECKS))` or the bare token.                                                                            | Declare `all(HEALTH_CHECKS)` or `lazy(all(HEALTH_CHECKS))`.                          |
| [`NEXUS_DISPOSED`](/errors/NEXUS_DISPOSED/)                       | A collector's dispose method calls the thunk after its contributions are disposed.                                                                                                                 | Do not call the thunk from a dispose method.                                         |
