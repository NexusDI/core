# Upgrading to 0.4

NexusDI 0.4 introduces a fundamental shift in how the container works: it moves from a "lazy, optimistic" model to a "static, validated" model. Instead of discovering wiring errors at runtime, NexusDI now validates the entire module graph before the first instance is ever created.

Because of this shift, the 0.4 API is significantly different from 0.3. This guide provides a sequential path to migrate your project.

## 1. Installation and Tooling

First, update your dependencies. 0.4 moves optional features (like decorators and testing) into their own packages to keep the core lean.

```bash
npm install @nexusdi/core@next
npm install -D @nexusdi/testing@next @nexusdi/errors@next @nexusdi/devtools@next
```

### TypeScript Update

NexusDI 0.4 requires TypeScript 5.4+ and Node 22.12+. Most importantly, you must **disable** `experimentalDecorators` and `emitDecoratorMetadata` in your `tsconfig.json`. 0.4 uses standard TC39 decorators and does not read compiler-emitted metadata.

## 2. Replacing Symbol Tokens

0.3 allowed the use of Symbols or Strings as tokens. 0.4 requires a `Token<T>` for any value that isn't a class.

**0.3 (Legacy):**

```ts
const NAV_CHARTS = Symbol('NavCharts');
container.set(NAV_CHARTS, { useValue: charts });
```

## 3. Moving to `static deps`

The `@Service` and `@Inject` parameter decorators are replaced by a `static deps` array on the class. This makes dependencies explicit and verifiable.

**0.3 (Legacy):**

```ts
@Service()
class QuantumComputer {
  constructor(@Inject(REACTOR) private reactor: IReactorCore) {}
}
```

## 4. Redefining Modules

`DynamicModule` and `@Module` classes are replaced by the `defineModule()` function. This allows for better type checking and a clearer distinction between the module definition and its configuration.

**0.3 (Legacy):** la used `DynamicModule.forRoot()` or `@Module` classes.
**0.4 (Current):** Use `defineModule()` and `forRoot()` / `forRootAsync()`.

## 5. Bootstrapping the Container

The `new Nexus()` and `set()` pattern is replaced by a single, atomic `Nexus.create()` call. This is where the static graph validation happens.

**0.3 (Legacy):**

```ts
const container = new Nexus();
container.set(REACTOR, { useClass: FusionReactor });
container.set(QuantumComputer);
```

## 6. Lifetimes and Scopes

- **Scopes:** `createChildContainer()` is replaced by `createScope({ request })`.
- **Transients:** `singleton: false` is now `lifetime: 'transient'`.
- **Eager Loading:** 0.3 built everything lazily. 0.4 builds all singletons at startup. Use `eager: false` to restore lazy initialization for expensive providers.

## Summary of API Changes

| 0.3 Concept              | 0.4 Replacement                |
| :----------------------- | :----------------------------- |
| `container.set()`        | `Nexus.create()` / `provide()` |
| `DynamicModule`          | `defineModule()`               |
| `createChildContainer()` | `createScope()`                |
| `@Service`               | `static deps` / `@Injectable`  |
| `Symptom tokens`         | `Token<T>`                     |
| `container.resolve()`    | `ship.resolve()`               |
