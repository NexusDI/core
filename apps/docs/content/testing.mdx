# Testing and Overrides

Testing a component that depends on a complex system (like a database or a remote API) is difficult if you have to set up the entire production environment just to run a single test.

NexusDI provides a specialized testing utility that allows you to build your real production graph but "swap out" specific providers for fakes.

## Unit Testing without the Container

For simple unit tests, you don't need a NexusDI container at all. Since your classes take their dependencies in the constructor, you can simply pass a fake object that implements the required interface.

## Integration Testing with `createTestingContainer`

When you need to test how a component interacts with the rest of the system, use `createTestingContainer`. This utility builds the real module graph but allows you to `override` specific tokens.

```ts file=examples/meridian/src/pages/testing.md region=override-reactor

```

The testing container is a full NexusDI container. It runs the same compiler and validation checks as production. If your override introduces a missing dependency or a circular reference, `create()` will reject just as it would in the real app.

## Overriding Modules

In some cases, you need to replace an entire set of providers. You can use `overrideModule` to replace one module with a stub module.

The stub module must export every token that the original module exported; otherwise, the container will reject the startup process with a `NEXUS_OVERRIDE_EXPORTS` error.

## Advanced Testing Patterns

### Preserving Lifetimes

By default, an override preserves the lifetime of the original provider. If a provider was transient in production, your fake will also be transient. You can override this by explicitly setting a `lifetime` in the override definition.

### Shared Base Builders

To avoid repeating the same overrides across multiple tests, you can create a base builder. Because the builder is immutable, you can derive specific test configurations from a single base without them interfering with each other.
