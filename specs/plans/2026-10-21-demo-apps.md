# Demo apps for 0.4 Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Ledger: `.superpowers/sdd/2026-10-21-demo-apps/progress.md`.

Goal: every published package runs in a demo app in CI. `examples/bridge-api` is the Meridian backend, `examples/bridge-console` replaces `examples/react-ssr`, four `examples/federation-*` projects show `@nexusdi/federation` and `@nexusdi/decorators` across real rspack bundles, core raises `NEXUS_CORE_NOT_SHARED` for a value from another copy of core, and a `demo-apps` CI job runs every demo's e2e suite.

Architecture: seven pull requests, each cut from `origin/release/0.4` and merged on its own. PR A changes core. PR B to PR D add or change apps under `examples/`. PR E adds the CI job. PR F writes the federation docs. PR G adds the vocabulary rows to the docs-site spec on `spec/docs-site`.

Tech stack: Node from `.nvmrc`, TypeScript 6.0.3, Vitest 5.0.5, Nx 23.3.0 (`@nx/react`, `@nx/rspack`, `@nx/module-federation`, `@nx/vitest`, `@nx/playwright`, `@nx/js`), `create-react-router` 8.5.0, `react-router` 8.5.0, `create-hono` 0.19.5, `hono` 4.13.13, `@hono/node-server` 2.1.5, `@module-federation/enhanced` 2.9.2, `@rspack/core` 2.2.9, `@playwright/test` 1.64.1, React 19.3.0.

Spec: `specs/2026-10-21-demo-apps-design.md` (decided, 2026-10-21). Section numbers below (§) refer to it. Also: the `nexusdi-ways-of-working`, `docs-page` and `nexusdi-release` skills.

## Global Constraints

- Each PR has its own branch from `origin/release/0.4` and its own worktree under `.claude/worktrees/<branch>`. Prefix every nx command and every `git commit` and `git push` with `NX_NO_CLOUD=true NX_DAEMON=false`.
- A branch stays under 40 commits. GitHub refuses a rebase merge above 100, and a fix round adds commits. A task is one to four commits.
- Never `--no-verify`, never a bare `git stash`, never a merge commit. Rebase onto `origin/release/0.4` before the PR, and force-push the PR's own branch only, with `--force-with-lease`. Open the PR against `release/0.4` without asking. Merging to `main` and any npm publish stay with the owner.
- Commit messages follow conventional commits with a scope from `commitlint.config.js`, a lowercase subject, and the trailer `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`. New scopes, each added by the task that creates its project, in the "private demo apps" block of `commitlint.config.js`: `bridge-console` (C1), `federation-shell`, `federation-cartography`, `federation-command`, `federation-contracts` (D1).
- Prose in docs, READMEs, comments and commits follows the writing rules of `nexusdi-ways-of-working`. Examples are interface-first and use only §7.1 names plus the rows of §9.2.
- Every app is scaffolded by its generator. The scaffold commit holds the generator's output and nothing else, so a reviewer reads the idiom apart from the edits. The next commit deletes what the app does not use.

### Heavy work

A heavy job is `npm ci`, a build of more than one project, any `e2e` target, `nx run-many`, or `npm run size`. On weekdays from 09:00 to 17:00 one heavy job runs at a time on the machine, across every worktree and agent, and each nx command in it takes `--parallel=2`. A task that needs a heavy job outside those hours runs it as usual. The controller serialises the heavy steps of parallel tasks in the ledger.

A worktree gets its dependencies with `npm ci` (a heavy job). A task that only reads code may read `node_modules` from the main checkout.

### Cleanup

Every task ends with this step before its review gate:

```sh
rm -rf libs/*/dist libs/*/test-output examples/*/dist examples/*/build \
  examples/*/.react-router examples/*/test-output apps/docs/.next tmp
```

The last task of each PR also runs `rm -rf node_modules */*/node_modules` in the worktree after the PR is merged and the worktree is no longer needed, then `git worktree remove`.

### Review gate

Each task ends with a review by an opus reviewer that did not write the task. The reviewer reads the task's diff against this plan and §, runs the task's test command, and reports findings. The implementer fixes them in new commits. The gate passes when the reviewer reports no finding. Each PR ends with a final review of the whole branch by an independent opus reviewer.
